# Commando Client

Frontend for Commando, a task management system: workspaces, tasks (table/cards views), assignees, dashboards and settings. It talks to the Commando server over REST (and optionally Socket.IO).

**Stack:** React 19, TypeScript, Vite, TanStack Router / Query / Table / Form, Shadcn (Radix + Base UI), `@emotion/styled`, Tailwind 4 (for Shadcn only), Orval (generated API client + MSW mocks), Biome, Vitest.

Coding conventions live in [`CLAUDE.md`](./CLAUDE.md).

## Prerequisites

- Node.js 22 (matches the Docker image) and npm
- A running Commando server (default `http://localhost:3000`), unless you use the mock API
- Optional: the SSO server (default `http://localhost:4000`) when `VITE_USE_SSO=true`

## Quick start

1. Install dependencies (this also installs the Lefthook pre-commit hook):
   ```bash
   npm install
   ```
2. Create your env file:
   ```bash
   cp .env.example .env
   ```
3. Start the backend, or set `VITE_USE_MOCK_API=true` to run on mocked data.
4. Start the dev server: <http://localhost:8080>
   ```bash
   npm run dev
   ```

## Configuration

All variables are `VITE_*`, read in `src/utils/env-utils.ts`. They are inlined at **build time**, so changing them requires a rebuild.

| Area | Variable | Purpose |
| ---- | -------- | ------- |
| General | `VITE_ENVIRONMENT` | `development` enables dev-mode behavior |
| API | `VITE_API_BASE_URL` | Server base URL (also used by Orval and the socket) |
| API | `VITE_API_PREFIX` | Path prefix appended to the base URL (default empty, example uses `api`) |
| Mock | `VITE_USE_MOCK_API` | `true` starts MSW with the generated handlers |
| Auth | `VITE_USE_SSO` | `true` enables SSO |
| Auth | `VITE_SSO_URL` | SSO server URL |
| Auth | `VITE_STATIC_TOKEN` | Dev-only static token, see [Auth](#auth) |
| Mesiba | `VITE_MESIBA_BASE_URL_API`, `VITE_MESIBA_S3_URL` | Mesiba API and S3 URLs; when empty (or mock mode), Mesiba features are off |
| Links | `VITE_CHAT_URL`, `VITE_CHAT_SUPPORT_PATH` | Support chat link |
| Links | `VITE_USER_GUIDE_URL`, `VITE_PORTAL_CATALOG_URL` | External links |
| Features | `VITE_AI_ENABLED` | Toggle AI features |
| Features | `VITE_SOCKET_ENABLED` | Toggle Socket.IO |
| Analytics | `VITE_MATOMO_ENABLED`, `VITE_MATOMO_SITE_ID` | Matomo tracking |

## Auth

- **Without SSO** (`VITE_USE_SSO=false`) and with `VITE_STATIC_TOKEN` set: every request carries a `static-token` header. The app acts as an admin user (`s0000000`). Use the user dropdown to override the UPN and `isBI` flag; they are sent as the `requestusername` and `is-bi` headers (stored in `localStorage`).
- **With SSO** (`VITE_USE_SSO=true`, not mock mode): on load the app calls `<VITE_SSO_URL>/sso/cookies`, stores the returned token in a cookie (on mobile: `localStorage`, via `sso/issue`) and refreshes it before expiry. If there is no valid session it redirects to `<VITE_SSO_URL>/sso/auth/comeback`. A 400/401 from the API triggers re-authentication. Requests are sent with credentials.
- Do not set `VITE_STATIC_TOKEN` in production builds. When it is set, the current user is derived from it and not from the SSO token.

## API client (Orval)

`src/api/` is committed to git and generated from the server's OpenAPI spec and is overwritten on every run (`clean: true`).

- Spec source: `${VITE_API_BASE_URL}/open-api/json` (read from `.env`, falls back to `http://localhost:3000`). The server must be running.
- Output: React Query hooks, TypeScript models in `src/api/model`, and MSW mocks, all split by tag.
- Requests go through `sendRequest` in `src/axios.ts`.
- Re-run `npm run orval` whenever the server API changes, and commit the result.

## Mock mode

Set `VITE_USE_MOCK_API=true` to run without a backend. `main.tsx` starts an MSW service worker (`public/mockServiceWorker.js`) with the Orval-generated handlers; unhandled requests pass through.

## Deployment

The build output is a static SPA in `dist/`. Any unknown path must fall back to `index.html`.

- **Vercel:** `vercel.json` rewrites all paths to `/`.
- **Static server:** `npm start` runs `serve dist --listen 8080 --single`. `vite preview` only accepts the hosts listed in `vite.config.ts` (`preview.allowedHosts`).
- **Browser target:** the build targets Chrome 83 (mobile).

### Release bundle (`run.sh`)

`run.sh` packages the source for transfer to an environment that builds the app itself. It requires Docker and SSH access to the GitHub repo.

1. Clones `BIData373/commando-client` (shallow) into a temp dir and checks out `dev`. It does not use your working tree, so uncommitted or unpushed changes are not included.
2. Builds the `Dockerfile` (`ubi9/nodejs-22`, `linux/amd64`), which copies the sources, runs `npm install`, and creates `/home/app/client.tar.gz`.
3. Starts a temp container, copies `client.tar.gz` into the current directory, then removes the container, image and temp dir.

Run it with:
```bash
./run.sh
```

Notes:
- The bundle contains source plus `node_modules` (installed on Linux amd64). It is **not** built; on the target you still need to supply the `VITE_*` values (e.g. a `.env`), run `npm run build`, and serve `dist/` (e.g. `npm start`).
- `.env` is gitignored, so no environment values end up in the bundle.
- The tarball is created from `/tmp/archive`, so the files sit under `tmp/archive/` inside the archive.

## Troubleshooting

- **`npm run orval` fails:** the server is not running, or `VITE_API_BASE_URL` points to the wrong place. Check that `<VITE_API_BASE_URL>/open-api/json` loads in a browser.
- **`routeTree.gen.ts` changes after `npm run dev`:** expected, TanStack Router regenerates it when routes change.
- **Stuck on "Authenticating...":** check `VITE_SSO_URL` and that the SSO server is up; or set `VITE_USE_SSO=false` locally.
- **Env change has no effect:** restart the dev server (or rebuild for production).
- **CORS or cookie errors with SSO:** the API and SSO must allow credentialed requests from the client origin (`http://localhost:8080` in dev).
- **`vite preview` shows "Blocked request":** the host is not in `preview.allowedHosts`.
